# DuitJom account flow update

Deploy the Worker and D1 migration before merging the accompanying portal changes. The portal requires `authFlowVersion: 2` from send requests and will show a service-update message if an old Worker is still running.

1. In the existing D1 database bound as `AUTH_DB`, run `migrations/0002-account-profiles.sql`. It adds tables without deleting existing users, sessions or challenges. For a new database, run `schema.sql` instead.
2. Deploy the updated `otp-worker.js` to the Worker serving `https://e-kyc.duitjom.my`. If that Worker also has other APIs, integrate `handleEmailAuth` into its existing handler; do not replace unrelated routes.
3. Keep the existing Mailjet credentials, sender, OTP pepper, Turnstile secret and `AUTH_DB` binding. Keep `ALLOWED_ORIGINS=https://www.duitjom.my,https://duitjom.my` and Turnstile action `auth`.
4. Ensure routes include `/api/send-otp`, `/api/verify-otp`, `/api/send-link`, `/api/verify-link`, `/api/session` and `/api/logout`. If `/api/*` already points to the Worker, no separate route is needed.
5. Keep the same public Google Firebase configuration and authorized domains. Google uses the existing Firebase OAuth provider; email accounts are checked in D1. Firebase-only accounts are not silently treated as D1 registrations. Existing verified D1 users can log in without re-registering.
6. Test with an owned email: new email login rejection, complete registration and OTP, logout, existing email registration rejection, OTP login, link login, expiry, resend and session restoration. Confirm receipt in the mailbox; a Mailjet accepted response is not proof of inbox delivery.
7. Merge the portal PR after the Worker is ready. Review the Pages deployment before directing customers to the new interface.

The new profile fields are stored in D1 after successful OTP verification; unverified profiles are staged against a challenge. MyKad and phone are never written to browser localStorage. Existing scheduled cleanup removes expired staged profiles. Keep the scheduled cleanup configured.

Missing `intent` now means login. A new account requires `intent: "register"` and a valid full name, MyKad and Malaysian phone number. Login links are generated by this Worker and sent through Mailjet; they use the existing session cookie, expire after five minutes and are single-use. Opening the link shows a confirmation button; a GET does not consume it.

## Verification

- Backend: `node --test workers/email-auth/otp-worker.test.js` (Node 24 with built-in SQLite).
- Browser: install Playwright, then `node tests/portal-browser.cjs` from the repo root. Set `CHROMIUM_PATH` if using a preinstalled Chromium. The browser suite mocks Firebase, Turnstile callbacks and Worker responses; it does not send real mail or process payments.
- The QR asset, recipient name, receipt UI and existing review timing are preserved. The existing receipt code displays a success state using a timer; it does not upload to a server. This change does not implement bank settlement or receipt storage.

The supplied welcome poster contains Malay text, which remains part of the image. HTML forms, features, news and payment labels use the chosen English, Malay or Chinese locale.
